# 03 — CI

> Part of [overview.md](overview.md). Depends on: 02

## Files

- `.github/workflows/ci.yml`, `release.yml`
- `.github/dependabot.yml`, `CODEOWNERS`, `pull_request_template.md`,
  `ISSUE_TEMPLATE/*`
- `scripts/ci-parity.test.ts`

## Steps

1. Jobs: `detect` · `guards` · `build` (gcc + clang matrix) · `standalone` ·
   `sanitizers` · `static` · `ci` (aggregate).
2. **`guards` is not gated on `detect`.** A guard whose subject is the whole tree
   must never have its execution gated on a subset of it — a docs-only PR is
   exactly the shape the vocabulary guard exists to catch.
3. `detect` runs `scripts/changed.ts`, the same `computeAffected` the local tier
   calls.
4. Every job carries `timeout-minutes`; a hung job holds the merge and teaches
   nothing.
5. Third-party actions pinned to a commit SHA, with the tag in a trailing comment.
6. The aggregate `ci` job grades `needs` explicitly, so a SKIPPED upstream job can
   never read as a pass.

## Tests

`scripts/ci-parity.test.ts` asserts: CI contains every gate command verbatim;
every job has a timeout; runners are pinned to one label; the aggregate job needs
every other job (so adding a job cannot silently escape the required check).

## Done when

- `bun test scripts/ci-parity.test.ts` green, and it goes red if `gate.ts` changes
  without `ci.yml`.
